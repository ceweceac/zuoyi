# 机器人认知双线：QA 知识库 vs product_background

> 目的：讲清楚 qa-bot 客服机器人「学知识」的两条路线各装什么、什么内容走哪条，
> 避免两条线内容打架或重复维护。配合 `.claude/skills/kb-ingest` 使用。

## 一、两条线是什么

机器人回答用户时，知识来自两个地方，机制完全不同：

| | **QA 知识库** | **product_background（产品手册）** |
|---|---|---|
| 存哪 | `qa_item` 表（当前 735 条） | `sys_setting` 表 `product_background` 字段（当前约 12000 字） |
| 怎么用 | 用户问题 → matcher 字面粗筛 + LLM 裁判精选 → **命中某条就返回该标准答案**（A级回答） | 拼进 LLM system prompt，让 LLM **每次回答都"读过"这本手册**后再答（B级兜底时生效） |
| 像什么 | 一本 **FAQ 问答卡片** | 一本 **随身产品说明书** |
| 注入脚本 | `import_dramatv_qa.py` | `learn_dramatv_doc.py` / `inject_dramatv_background.py` |

## 二、什么内容走哪条（判断规则）

**核心判断：能不能拆成清晰的「一问一答」？**

### 走 QA 知识库 ✅
- 有明确问法的点状知识
- 例："怎么新建画布？""图生视频怎么用？""计费主体怎么绑定？"
- 特点：用户大概率会**这样问**，且答案**确定、可固定**
- 优势：命中即返回标准答案，稳定、不靠 LLM 发挥、可审核

### 走 product_background ✅
- 讲不清边界、需要整体理解的背景知识
- 例：产品定位（"DramaTV 是面向短剧团队的 AI 工作台"）、机制原理（三大入口怎么配合）、设计理念
- 特点：用户问法**千变万化**，没法穷举成 QA，但 LLM "读过"就能灵活回答
- 优势：兜底时让 LLM 有产品全局认知，不会瞎编

## 三、为什么两条都要、怎么配合

```
用户提问
   │
   ├─ matcher 在 QA 知识库找 → 命中 → A级标准答案（首选，最稳）
   │
   └─ 没命中 → LLM 兜底，此时 product_background 生效
              → LLM 凭"读过的手册"灵活回答（B级）
              → 手册里也没有 → 坦诚说没找到 / 转人工
```

**两条线是「精确优先 + 背景兜底」的关系，不是二选一。**

## 四、维护纪律（避免两条线打架）

1. **同一知识别两条都塞冗长版本**：QA 放精炼问答，background 放背景脉络。
   例：「图生视频怎么用」→ QA 放操作步骤；background 只需提一句"支持文生/图生/首尾帧视频"。

2. **background 控制在 ~12000 字内**：它进每次 system prompt，太长会膨胀 token、拖慢回答、稀释重点。
   新增产品认知优先进 QA 库（QA 按需检索，不占每次 prompt）。

3. **改了 background 要 store.reload()**：`pipeline.handle` 检测到影响 prompt 的字段变更会自动 reload；脚本直接改库的，生产需重启。

4. **两条线都不碰模型计费/掺水**：那是 API 健康检查平台的事，与客服机器人认知无关。

## 五、当前 DramaTV 认知落地情况

- **QA 知识库**：DramaTV 相关约 57 条（本次使用指南导入，已去重、已归入 6 大标准分类）
- **product_background**：DramaTV 完整使用指南全文（约 12000 字，`learn_dramatv_doc.py` 注入）
- 两者配合：常见问题走 QA 精确命中；冷门/灵活问法由 LLM 凭手册兜底
