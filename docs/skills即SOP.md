# skills 即 SOP：qa-bot 的技能体系

> 借鉴 Hermes/OpenClaw 的核心理念之一："任何要解释两遍的工作流，就该变成 skill"。
> 本文讲清 qa-bot 的 skill 体系：是什么、有哪些、为什么、还缺哪些。

## 一、什么是"skills 即 SOP"

**SOP = 标准作业流程（Standard Operating Procedure）。**

Hermes 作者的规矩：一个流程如果你要跟人（或跟 AI）解释第二遍，就该把它写成一个
skill 文档固化下来。这样下次直接"调 skill"，不用重新讲一遍步骤、参数、注意事项。

关键点（Hermes 的设计）：
- **skill 是文档，不是代码**——它是给 AI 读的操作手册（SKILL.md），AI 读完按它做事。
- **每次只加载需要的那个**——靠 description 触发，不膨胀上下文。
- **沉淀团队知识**——流程跟着 skill 走，不散落在某个人脑子里或聊天记录里。

## 二、qa-bot 现有的 3 个 skill

| skill | 干什么 | 把哪些手工活固化了 |
|---|---|---|
| **kb-ingest** | 文档 → 知识库流水线 | 拆QA→去重→打标→导入→失败回流（覆盖 7 个脚本） |
| **verifier-qabot** | 隔离实例验证改动 | 起隔离实例、按surface驱动、verify格式报告 |
| **deploy-qabot** | 生产重启/上线 SOP | 备份→停→起→验健康→验钉钉（5步） |

每个 skill 都对应一类"以前要反复解释"的流程：
- 每次导文档进 KB → 现在调 kb-ingest
- 每次验证改动对不对 → 现在调 verifier-qabot
- 每次重启上线 → 现在调 deploy-qabot

## 三、为什么这 3 个值得做成 skill

按"解释两遍"的标准，这三件事都被重复做过很多次：

| 流程 | 重复了多少次 | 不做 skill 的代价 |
|---|---|---|
| 文档导KB | DramaTV指南、gap分析等多轮 | 每次记不清"先跑哪个脚本、什么参数"，漏打域标签（真踩过坑）|
| 验证改动 | 每次改代码都要验 | 每次重搭隔离环境，曾因没开关导致钉钉重试卡死启动 |
| 重启上线 | 这几天 10+ 次 | 漏备份会丢数据、漏验钉钉机器人哑了没人知道 |

## 四、skill vs 脚本 vs 配置（别混）

qa-bot 里三种东西容易混，理清：

| | 是什么 | 例子 | 给谁用 |
|---|---|---|---|
| **skill** | 给AI读的流程手册(SKILL.md) | kb-ingest | AI助手/Claude |
| **脚本** | 实际执行的代码(.py/.sh) | import_dramatv_qa.py | skill 调用脚本干活 |
| **配置** | 运行时开关(DB/.env) | daily_brief_enabled | 机器人自己读 |

关系：**skill 是"怎么做"的说明书，脚本是"动手"的工具，配置是"机器人的设置"。**
skill 串起多个脚本，告诉AI按什么顺序、什么纪律去用它们。

## 五、还可以做成 skill 的（按需，不急）

按"解释两遍"标准，未来如果这些重复出现，可考虑沉淀：

- **回归测试 SOP**：改 KB tags/域标签前后，跑 regression_test.py 对比命中率（已有脚本，用多了可包成 skill）
- **盲区补全 SOP**：每日简报/实时盲区告警发现的缺口 → 走 kb-ingest 补 KB（目前靠人记，可固化成"看到盲区告警后怎么处理"）

不必为做而做——**只有真重复的流程才值得**。这正是 Hermes 的克制：作者 115 个 skill
都是被真实重复"逼"出来的，不是一次性的事。

## 六、和 Hermes 的差异（诚实说明）

| | Hermes skill | qa-bot skill |
|---|---|---|
| 加载方 | Hermes 运行时（给机器人自己用） | Claude/AI助手（给开发运维用） |
| 作用 | 让 Agent 自主执行业务SOP（如发YouTube视频） | 让AI助手按规范帮你维护这个机器人 |

**关键区别**：Hermes 的 skill 是"机器人自己干活的本事"；qa-bot 的 skill 是
"维护这个机器人的标准流程"。前者面向机器人自主，后者面向人机协作维护——
这符合 qa-bot 作为"被动客服"的定位（它不该自主乱跑，但维护它的流程该标准化）。
